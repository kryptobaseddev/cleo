Implements spec `cleodocs-rearch-design` §4/§10 (D11165): the ledger stays the operational authority and ADR docs stay curated records authored at graduation — never generated from the ledger. The new `decision_adr_links` table (SYNCING, append-only, portable-project) links both tiers with a natural composite key so concurrent identical links coalesce on apply; unlink is a one-way monotonic tombstone latch (`status` → 'revoked'), never DELETE or re-link — enforced BOTH by the local accessor and at merge (T13597): `SYNC_MERGE_RULES` declares 'revoked' an absorbing state with no leave op (`docs.decision-adr-links.revoke-monotonic`, group `[status, revoked_by]`), so a concurrent same-uid link op from another device is refused by the merge engine and cannot resurrect the tombstone by per-field LWW. `cleo docs fetch <adr-slug>` surfaces the linked `D####` decisions on the envelope (`linkedDecisions`), and `cleo memory decision.find` attaches each decision's linked ADR slugs (`linkedAdrs`) — one link row, both directions. Canonical accessors live in `store/decision-adr-links.ts` (gate-28 clean, `@sync-invariant` tagged); the table is declared in ROW_IDENTITY (gate 37), classified (gate A), carries a deterministic forward-only migration with no DML (gate 36, AC4: the ~360 existing decisions are untouched), and the gate-38 registry entry is implemented with a merge-engine race test (revoke on A, stale link on B, merge → stays revoked, in every op order). The docs taxonomy/canon routing is unchanged — the ADR lifecycle itself does not change (AC3).
